## 0. 사용자와 일하는 방식 (가장 중요)

- 사용자(혜연)는 **코딩을 모른다.** 한국어로, 쉬운 말로 짧게 답한다. 어려운 말(브랜치, 커밋, 셰이더 등)은 쓰지 않거나 풀어서 말한다.
- 작업이 끝나면 **스크린샷을 보여 주고**(SendUserFile, display: render) 무엇이 바뀌었는지 짧게 정리한다.
- 사용자는 휴대폰 캡처로 문제를 알려 준다. **빨간 동그라미가 문제 위치.**
- 지금까지는 사용자가 **"반영해줘 / 배포해줘"라고 하거나, 고쳐 달라는 요청이면 바로 사이트(main)에 올려 왔다.** 큰 기능을 새로 넣을 때는 먼저 보여 주고 물어본다.
- **솔직하게.** 확인 못 한 것은 확인 못 했다고 말한다. 특히 작업 컴퓨터에서는 **실제 사이트와 Supabase에 접속이 막혀 있다(프록시 403)** → 같이 접속·물소리·실제 휴대폰 성능은 사용자에게 확인을 부탁한다.
- 무겁게 만들지 않는다(사용자: "서버 부하 너무 있게 하지 마", "외부 공간에 너무 힘쓰지 마").

## 1. 지켜야 할 규칙

1. **Supabase Secret 키(sb_secret_, service_role)는 절대 받지 않는다.** Publishable 키만.
2. 커밋·코드·문서에 AI 모델 이름을 적지 않는다.
3. PR은 사용자가 말할 때만.
4. 실제 회사·브랜드 로고를 베끼지 않는다(참고 사진은 분위기만).
5. 직함은 바꾸지 않는다 — 결투는 **레벨 숫자와 패배자 칭호만**.

- **📋 업무 요청** (`src/requests.js`): 위쪽 📋 업무 버튼(빨간 숫자 = 아직 안 끝난 받은 요청) 또는 왼쪽 접속자 이름 누르기 → 받는 사람·제목·내용·마감일. 받은 사람은 ▶ 시작하기 → ✔ 완료하기. 실시간 알림은 이벤트 `{t:'req'}` + 화면 위 알림(`toast`), 접속 안 했을 때 온 것은 들어올 때와 90초마다 확인. 표가 없으면 브라우저에만 저장. 상태·시각만 고칠 수 있게 SQL에서 열 권한 제한.
- **엘리베이터 창**: 위층이 위(RF→1F). 열리면 캐릭터 멈춤(`floorOpen`, 걷던 키 반복 무시 `heldAtOpen`), ↑↓/W·S로 고르기, Enter·E·Space로 이동, 숫자 1~5, Esc. 지금 층은 못 고름(`floorBlocked`, 건물 밖 보기에서는 허용).

- **가구 윗면 높이 자동 맞춤**: `Kit.fitTops` — 부딪힘 상자를 넓게 덮는 조각의 실제 윗면(±0.35m 안)으로 `top`을 맞춤(발이 가구 속에 파묻히지 않게). 직접 정하고 싶으면 `fixedTop: true`.
- **조작**: WASD/조이스틱, 바닥 탭하면 길 찾아 이동(A*), 점프(가구 위에 올라섬), 앉기(겹쳐 앉기 방지), 채팅(보낸 뒤 이어서 입력), 공지판, 샌드백 게임.

- **요즘 작업 컴퓨터가 매우 느림**: 페이지가 들어가는 데만 몇 분 걸릴 수 있음 → 스크립트의 waitForFunction timeout을 크게(1500000) 하고, Bash는 `run_in_background`로 돌린 뒤 알림을 기다린다. 장면 전환(fly)·물리처럼 프레임 수(dt, 최대 0.05)로 움직이는 건 테스트에서 아주 느리게 보임 — 실제 기기 문제 아님.
- 크롬 옵션: `--use-gl=angle --use-angle=swiftshader --enable-unsafe-swiftshader --no-proxy-server`. 매우 느림(2~10fps) → 성능 판단은 실제 휴대폰으로.
- 테스트는 `config.js`를 가로채 `supabaseUrl: ''`로 바꿔 **로컬 데모 모드(같은 브라우저 탭끼리)** 로 돈다.
- `page.goto(..., { waitUntil: 'commit' })` 사용(가끔 'load'가 멈춤). `window.__work`에 디버그용 상태가 열려 있다(`player, cam, duel, goFloor, chooseFloor, findPath, collide, av` 등).
- 화면에 시스템 메시지가 겹치면 `#chatToggle`을 눌러 채팅을 접고 찍는다.

## ⛄ 눈싸움장 (`src/snow.js`, 자리는 building.js의 `SNOW`)
- 사옥 뒤쪽(북쪽) 정원 x -9.5~9.5, z -21.5~-9.5. 나무 울타리(부딪힘 tall)로 둘러싸고 사옥 쪽(남쪽) 가운데에 간판 아치 문(폭 2.8m). 원래 있던 북쪽 디딤돌은 뺌(garden.js). 1층 로비 뒷문(`NORTH_DOOR` x -1.15~1.15, 북쪽 유리벽 가운데, 문틀 · 차양 · 매트 · '⛄ 눈싸움장 ↑' 간판)에서 돌길로 눈싸움장 문까지 이어짐. 구역 이름 `snow`('⛄ 눈싸움장').
- 안에 있을 때만: 위쪽 점수판(#snowHud), 휴대폰 ❄ 버튼(#btnSnow), F 키 → `snowFight.throw()`. **캐릭터가 보는 방향**(player.ry, 11-25 버그 수정: 카메라 방향이면 휴대폰에서 늘 북쪽으로만 날아감)으로 초속 14m · 위로 2m/s(사거리 약 9m), 0.55초마다 한 번. 17° · 9m 안의 사람/눈사람으로 살짝 조준 도움.
- 알림: 던질 때 `{t:'snow',k:'throw',id,by,x,y,z,vx,vy,vz}`, 다른 화면은 0.3초 늦게 같은 궤적을 그림. 맞았는지는 **맞은 사람 화면**이 판단 → `{k:'hit',bid,by,id,name}` → 던진 사람 맞힘 +1 · 1,000원(11-24 사용자 요청으로 300→1000). 눈사람 과녁(Date.now로 모두 같은 자리) 100원. 하루 최대 9만 원(11-25 사용자 요청 1만→9만, localStorage `work-snow`, 기기별).
- 눈덩이는 울타리 밖으로 못 나감, 울타리 안 사람만 맞음. 눈 벽 4개가 막음.
- 확인: 데모 탭 두 개로 맞힘/맞음 · 상금, 밖에 있는 사람은 안 맞음, 문으로 길찾기 확인. **실제 휴대폰 손맛(버튼 위치 · 거리)은 사용자 확인 필요.** 사용자는 '눈 뭉치기(개수 제한)' 대신 지금 방식으로 먼저 해 보기로 함.

## 🎄 크리스마스 출석 이벤트 (`src/advent.js`)
- 기간 `ADVENT` 2026-11-24 ~ 12-25. 들어올 때(`adventCheckIn`, 업데이트 소식 창이 닫힌 뒤) 오늘 날짜를 지갑 `stocks.__xmas`에 넣고(하루 한 번 저장) 조건 맞는 선물을 `stocks.__items`에 넣음(`money.stampDay` · `money.grant`). 새로 찍히면 출석 창이 뜸(도장 애니메이션, 새 선물은 위에 크게 + 착용 버튼).
- 선물(`XMAS_REWARDS`): 출석 1 루돌프 머리띠(head) · 3 니트 목도리(neck) · 6 산타 보따리(bag) · 10 산타 부츠(새 자리 `feet`, 두 다리에 붙음) · 15 산타 코트(body) · 21 눈꽃 날개(back) · 12/25 당일 크리스마스 스타(top, 빙글빙글). 모양은 avatar.js `makeAcc`.
- **사용자 요청: 부티크에서 절대 팔지 않음, 출석해야만 받음.** 부티크 '🎄 출석 한정' 칸에 진열만 하고 버튼은 '🔒 출석 N일'(누르면 출석 창). 사용자가 '진짜 깔쌈하게, 누구나 탐내게' 원함.
- 선물 카드 그림은 내 캐릭터가 착용한 모습을 따로 그림(작은 WebGL 하나, 창 열 때, 모습 바뀌면 다시).
- 착용 개수 제한 4 → 8(`setAcc`). 확인: `tools/check/xmas.html`(7종 앞 · 뒤), `hat.html?acc=rudolph&zoom=1`.
